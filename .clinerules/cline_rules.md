# Universal Vibe-Coding Rules

1. **Автономное исследование:**
   - Перед стартом задачи САМ изучи проект: прочитай конфигурационные файлы (package.json, requirements.txt, Cargo.toml, Makefile и т.д.) и структуры папок. 
   - Не спрашивай у пользователя технические детали — выясняй их сам через чтение файлов.

2. **Защита от поломок (Defensive Coding):**
   - Не переписывай файлы с нуля, если нужно внести точечные правки.
   - Никогда не оставляй "заглушки" (`// TODO: implement later`). Пиши сразу полный рабочий код.
   - не оставляй комментарии вообще

3. **Цикл авто-валидации:**
   - После ЛЮБОГО изменения файлов загляни в терминал и запусти команду проверки/сборки/линтера, которая используется в проекте.
   - Если после твоих правок появились ошибки — исправь их САМ перед тем, как отчитываться пользователю.

4. **Самостоятельность при отсутствии элементов:**
   - Если для выполнения задачи не хватает файла, папки или конфигурации — САМ создай их с правильной базовой структурой, не задавая лишних вопросов.
